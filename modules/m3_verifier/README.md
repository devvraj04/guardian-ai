# Module 3 — Dual Groundedness Verifier (`m3_verifier`)

## 1. Overview & Purpose
Module 3 is the core load-bearing component of GUARDIAN. It enforces the **Sacred Verification Gate** (RULES.md §1):
> **No `Claim` object may reach a user-facing response without a corresponding row in `verification_results`.**

The verifier executes a dual semantic and numeric evaluation to ensure that every output generated by the LLM, the deterministic calculators, the consistency matching layer, and the conversational chatbot is strictly grounded in verifiable mathematical ground truth or regulatory directives.

### 2.1 Semantic Check (RoBERTa-MNLI)
- **Model**: `roberta-large-mnli` running locally (GPU accelerated via PyTorch/CUDA when available, CPU fallback).
- **Evidence Retrieval**:
  - Pulls regulatory clauses from `rbi_corpus`.
  - Pulls user contract chunks from `user_documents` via the Phase 5 secure scoped wrapper (`query_user_documents(user_id, loan_id)`).
- **Entailment Logic**:
  - Direct Contradiction ($\ge 0.50$): sets `error_type="semantic_mismatch"`.
  - Entailment ($\ge 0.55$): sets `semantic_verdict="grounded"`.
  - Neutral / Low entailment: sets `error_type="insufficient_evidence"`.

### 2.2 Numeric Check (Deterministic Pure Python)
- Strictly imports `recompute_apr` (Module 1) and `assess_serviceability` (Module 1b) per RULES.md §1.7. Zero reimplementation of arithmetic math.
- Extracts figures, percentages, and currencies from `claim_text` and validates against ground truth using strict tolerances:
  - Effective APR: $\le 0.05\text{ percentage points}$
  - Monthly EMI: $\le ₹1.00$
  - Debt-to-Income (DTI): $\le 0.5\%$ ($0.005$)
- Flagged on any arithmetic divergence (`error_type="numeric_mismatch"`).
